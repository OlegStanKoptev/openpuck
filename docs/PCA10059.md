# OpenPuck на Nordic nRF52840 Dongle (PCA10059)

Эта ветка собирает OpenPuck под официальный USB-донгл Nordic **PCA10059** с заводским загрузчиком
**Open DFU** (на USB он виден как `Nordic Semiconductor — Open DFU Bootloader`, `1915:521F`). Перетаскивать
`.uf2` на такой донгл нельзя: он не появляется как диск. Прошивка идёт через `nrfutil`.

## Чем эта сборка отличается от upstream

Загрузчик PCA10059 занимает флеш с `0xE0000` до конца. Upstream рассчитан на загрузчик с `0xF4000` и
кладёт настройки на `0xED000–0xF3FFF`, а диагностический «чёрный ящик» — на `0xE8000`. На донгле это
стёрло бы загрузчик. Здесь раскладка сдвинута ниже:

| Область | Адреса |
|---|---|
| MBR + SoftDevice S140 6.1.1 | `0x00000–0x25FFF` |
| OpenPuck | `0x26000–0xD7FFF` |
| «чёрный ящик» `fault_diag` | `0xD8000` |
| настройки и сопряжения (InternalFS) | `0xD9000–0xDFFFF` |
| загрузчик Nordic, не трогается | `0xE0000–0xFFFFF` |

Изменения: `Makefile` (цели `*-pca10059`), `OpenPuck/board_config.h`, `OpenPuck/fault_diag.cpp`,
`OpenPuck/status_led.cpp`, `tools/pca10059/nrf52840_s140_v6_pca10059.ld`. Адрес InternalFS зашит в ядре
Adafruit, поэтому `make build-pca10059` копирует его библиотеку в `build/`, правит адреса в копии и
подключает её через `--library`; само установленное ядро не меняется.

Поскольку загрузчик не трогается, донгл нельзя «окирпичить» прошивкой: в DFU он всегда входит кнопкой.

## Режим DFU

Нажать боковую кнопку **RESET** на донгле. Красный светодиод начинает плавно мигать, в системе появляется
`Open DFU Bootloader`. Проверка:

```bash
nrfutil device list
```

**После каждой прошивки донгл нужно вынуть и вставить обратно** — сам он после DFU на USB не появляется.

## Установка с нуля из готовых файлов

Нужен только `nrfutil` от Nordic.

1. Установить `nrfutil` и его команды (macOS, Apple Silicon и Intel — один бинарник):

   ```bash
   mkdir -p ~/.local/bin
   curl -fL -o ~/.local/bin/nrfutil https://files.nordicsemi.com/artifactory/swtools/external/nrfutil/executables/universal-apple-darwin/nrfutil
   chmod +x ~/.local/bin/nrfutil
   export PATH="$HOME/.local/bin:$PATH"
   nrfutil install device nrf5sdk-tools
   ```

   Предупреждение `JLinkARM DLL not found` можно игнорировать: J-Link для DFU не нужен.

2. Скачать из релиза этой ветки `s140-6.1.1-pca10059.zip` и `OpenPuck-pca10059.zip`.

3. SoftDevice, один раз на донгл. Ввести донгл в DFU (RESET) и:

   ```bash
   nrfutil device program --firmware s140-6.1.1-pca10059.zip --traits nordicDfu
   ```

4. Прошивка. Снова RESET и:

   ```bash
   nrfutil device program --firmware OpenPuck-pca10059.zip --traits nordicDfu
   ```

5. Переподключить донгл. Он должен определиться как **Steam Controller Puck** (`28DE:1304`).

## Сборка из исходников

```bash
brew install arduino-cli
pipx install adafruit-nrfutil
arduino-cli config init
arduino-cli core update-index --additional-urls https://adafruit.github.io/arduino-board-index/package_adafruit_index.json
arduino-cli core install adafruit:nrf52 --additional-urls https://adafruit.github.io/arduino-board-index/package_adafruit_index.json
```

Плюс `nrfutil` из шага 1 выше. Проверено с ядром `adafruit:nrf52@1.7.0`.

`adafruit-nrfutil` падает на шаге постобработки при ASCII-локали, поэтому:

```bash
export LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
```

SoftDevice S140 6.1.1 (один раз). HEX лежит в репозитории загрузчика Adafruit:

```bash
curl -fL -o s140_nrf52_6.1.1_softdevice.hex https://raw.githubusercontent.com/adafruit/Adafruit_nRF52_Bootloader/master/lib/softdevice/s140_nrf52_6.1.1/s140_nrf52_6.1.1_softdevice.hex
make provision-pca10059-softdevice SOFTDEVICE_HEX=$PWD/s140_nrf52_6.1.1_softdevice.hex
```

Прошивка (донгл в DFU):

```bash
./gen_version.sh
make deploy-pca10059
```

`deploy-pca10059` = `build-pca10059` + `package-pca10059` + `flash-pca10059`; их можно звать по отдельности.
Готовый пакет — `build/pca10059/OpenPuck-pca10059.zip`.

## Сопряжение и настройка

Как в основном [README](../README.md#pairing): донгл и контроллер одновременно подключить к компьютеру
кабелями с данными и запустить Steam. Настройки — [веб-конфигуратор](https://safijari.github.io/openpuck/)
в Chrome или Edge.

В этой сборке, как и в upstream-сборке для Raytac, **не работают** вкладка обновления прошивки и кнопки
«Serial DFU» / «UF2 DFU» в конфигураторе: они рассчитаны на загрузчик Adafruit. Обновление — только через
RESET и `nrfutil`.

## Если донгл застрял в режиме без WebUSB

Режимы PS3 и Original Xbox не отдают WebUSB, так что конфигуратор их не видит. Если в конфигураторе
включено «запоминать режим», такой режим переживает переподключение, а выйти из него комбинацией
«4 задние кнопки + A» можно только с сопряжённым контроллером.

Выход — прошить вариант со сбросом `OpenPuck-pca10059-factory-reset.zip` (RESET, затем
`nrfutil device program --firmware OpenPuck-pca10059-factory-reset.zip --traits nordicDfu`, переподключить).
При первой загрузке он стирает настройки и сопряжения и возвращает Steam-режим; дальше работает как обычная
прошивка, оставлять его можно. Сброс срабатывает один раз на git-хэш сборки: повторная прошивка того же файла
ничего не сотрёт. Из исходников:

```bash
make build-pca10059 EXTRA_FLAGS="-DOPK_FACTORY_RESET=1" && make package-pca10059 flash-pca10059
```

## Ошибки

| Симптом | Причина и что делать |
|---|---|
| `SdVersionFailure` при прошивке SoftDevice | пакет собран без `--sd-req 0x00`, а на заводском донгле SoftDevice нет. Использовать `provision-pca10059-softdevice` или файл из релиза |
| `SdVersionFailure` при прошивке OpenPuck | SoftDevice S140 6.1.1 не установлен — сначала шаг 3 |
| после прошивки донгла нет на USB | вынуть и вставить обратно |
| `RuntimeError: Click will abort further execution…` при сборке | ASCII-локаль, см. `LC_ALL` выше |
| донгл не входит в DFU | нажать RESET ещё раз, проверить кабель (нужен кабель с данными) |
